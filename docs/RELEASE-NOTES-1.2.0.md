# Variable-Trace 1.2.0

基于 MCUViewer 1.1.0（GPLv3，作者 Piotr Wasilewski）修改并更名。上游此后闭源，
本项目在 1.1.0 那份快照上独立演进。

解压即用：`Variable-Trace.exe` 与随包的 DLL 必须放在同一目录，手册是同目录的 HTML 文件。

## 相对上游 1.1.0 的主要变化

| | 内容 |
|---|---|
| **任务视图** | 一个新的视图，直接读 FreeRTOS 内核自己的结构：谁在跑、谁在等、在等什么、等了多久。不需要改编译选项，也不需要固件配合 |
| **自动化接口** | HTTP 上的 MCP（默认 `127.0.0.1:7807`，裸 JSON-RPC）与一条裸 TCP 命令通道（默认 7808，默认关闭），供脚本与 PLC 驱动 |
| **名称** | 程序名、窗口标题、配置目录（`%APPDATA%/Variable-Trace/`）、日志目录都改了 |

## 这一版（1.2.0）的重点

### 任务视图

- **左右两区**：左边是采集状态、摘要、发现、筛选和任务表；右边是时间线、同步对象、
  钉住时刻、选中任务详情。
- **发现（Findings）**：疑似死锁、无超时等待、就绪饥饿、优先级继承四条。带数量、
  分三档严重度（`!` 红 = 会卡住、`!` 橙 = 警告、`i` = 提示），整行可点，右键可复制
  整条关系链。
- **选中任务详情**：地址、所在内核链表、是否优先级继承、栈用量的**读数年龄**、
  时间占比的**分母**。一键复制成一行。
- **时间点详情**：钉住时间线上的某一刻，右栏说明那一刻在跑谁、四类状态各几个。
- **时间线**：泳道按基础优先级排列（可切换成跟随表格顺序），点泳道名选任务、
  点绘图区钉时刻。切换记录可来自目标内存环、ITM/SWO、RTT 三种载体。

### 修复

| 现象 | 原因 |
|---|---|
| 采集启动一两秒后整个采集停住、界面还在但不更新 | J-Link 一次读完整个任务控制块时卡在 DLL 内部的同步 USB 读上。改成按 64 字节包边界分块读 |
| 任务表 Priority 列出现八位数 | 读了就绪表里一个从不被写入的字段。优先级改为取自就绪表的索引 |
| 变量地址变成 `0x00000000`，或外设地址取不到 | 符号解析失败时返回了 0；`stoi` 对超过 INT_MAX 的地址抛异常 |
| 探针偶发读回半块数据被当成完整数据 | `JLINKARM_ReadMemEx` 返回的是搬运字节数，原来只要非负就算成功 |

## 已知限制

| 限制 | 说明 |
|---|---|
| 个别探针会在读控制块时卡住 | 到「采集设置」里关掉 `Task view: read control blocks`。任务表会只剩状态和地址，变量视图不受影响 |
| SWO 与任务视图读数不能共存（J-Link） | 一颗 J-Link 同时只服务一条连接 |
| RTT 通路当前不可用 | 目标侧已就绪，J-Link 的 DLL 能找到控制块但读不出数据。默认的内存环通路不受影响 |
| 任务视图只能看到被调度过的东西 | 内核不维护"切换次数"，所以没有这一列 |
