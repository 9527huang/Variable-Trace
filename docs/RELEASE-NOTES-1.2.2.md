# Variable-Trace 1.2.2

基于 MCUViewer 1.1.0（GPLv3，作者 Piotr Wasilewski）修改并更名。上游此后闭源，
本项目在 1.1.0 那份快照上独立演进。

解压即用：`Variable-Trace.exe` 与随包的 DLL 必须放在同一目录，手册是同目录的 HTML 文件。

> 1.2.1 之后又改了六处，都在任务视图里：**离线记录**是新的，其余五处是把"表和图自己会动"
> 这件事一件件治掉。已经用过 1.2.1 的直接换这一版，工程文件与全局设置兼容。

## 这一版（1.2.2）的重点

### 离线记录：把一段现场带回去看

采集时按一次 `record`，界面看到的每一轮都写进 `.vtrec` 文件；之后不接探针打开它，
在时间线上点一下就能回到那一刻的表格、发现和泳道。

- 记录的是**每一轮的完整快照**，不是另一套对目标的建模：回放时看到的就是当时看到的。
- 任务视图的轮次约两秒一轮，所以十分钟的记录只有几百轮、几兆字节。
- 时间线在回放时就是进度条：钉住一个时刻，整张表换成那一刻的样子。
- 五个新工具给脚本用：`start_rtos_recording` / `stop_rtos_recording` /
  `open_rtos_recording` / `close_rtos_recording` / `show_rtos_round`。

### 表格不再自己动

一个跑着的系统里，表格原来每隔半秒重排一次，原因是四件互相独立的事叠在一起：

| 原来 | 现在 |
|---|---|
| 行来自"这一轮读到了谁"，一轮读到 11 个、下一轮 14 个 | 行来自**这次会话见过的全部任务**；这一轮没读到的行留着，整行画 `/`，压暗 |
| 默认按"问题"排（栈告警、阻塞、继承在前），谁一阻塞就跳上去 | 默认**按任务名**排，行钉住；`back to problem order` 一键切回去 |
| 泳道高度 = 可用高度 ÷ 条数 | 每条泳道**固定高度**；装不下就在框内滚动（任务名那半滚轮，或 `Shift`+滚轮） |
| 时间线的框高跟着筛出来的条数变 | 框高按**会话里的任务数**算，筛选不改变框的大小 |

`-` 和 `/` 现在是两件事：`-` 是这一轮读到了这个任务、但这个字段没读数；`/` 是这一轮
根本没读到这个任务。

### 泳道配色

四种状态的颜色按**红绿色弱**重挑：运行浅绿、就绪橙黄、阻塞琥珀、挂起中性灰，
"没有读数"深棕。三个暖色都在红绿这条轴上，分开它们的是明度——近白的绿、亮的黄、深的琥珀。
按模拟量，最近一对的 CIELAB 距离从 9 提到 30。色带也不再半透明叠在深色底板上：那样叠完
黄和琥珀都是褐色，把明度差抹掉了。

## 已知限制

| 限制 | 说明 |
|---|---|
| 个别探针会在读控制块时卡住 | 到「采集设置」里关掉 `Task view: read control blocks`。任务表会只剩状态和地址，变量视图不受影响 |
| SWO 与任务视图读数不能共存（J-Link） | 一颗 J-Link 同时只服务一条连接 |
| RTT 通路当前不可用 | 目标侧已就绪，J-Link 的 DLL 能找到控制块但读不出数据。默认的内存环通路不受影响 |
| 任务视图只能看到被调度过的东西 | 内核不维护"切换次数"，所以没有这一列 |
| 右键交互（表头列菜单、复制关系链）未做脚本化验证 | 本机自动化无法向内注入右键，功能本身可用，需要人工点一次 |
| 录制跨采集会收尾 | 一次采集一份记录：时钟随会话重置，跨会话写下去会在一根轴上画出两段不相干的运行 |
