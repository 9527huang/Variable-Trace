# 任务视图：目标侧接入要求

本文面向需要把 FreeRTOS 目标接入任务视图的固件开发者，集中说明目标工程的编译、配置、事件记录、传输、资源和验收要求。主机侧的功能范围、界面和实施顺序见 [任务视图开发计划](../analysis/任务视图-开发计划.md)；mdkdebug Trace 的具体集成边界、阶段和验收门槛见 [mdkdebug Trace 接入任务视图：开发计划与验收方案](mdkdebug-Trace-任务视图集成开发计划.md)。

本文是目标侧接入契约。示例固件用于验证契约，不替代契约本身。主机和目标实现若与本文冲突，应先更新并版本化契约，再修改代码。

- 文档状态：目标侧协议草案，快照要求已有验证固件，事件组件尚未实现
- 适用范围：首版 FreeRTOS、Cortex-M3/M4；其他 RTOS 和多核目标沿用模型但需单独适配
- 协议原则：任何不兼容的线格式或生命周期变更都必须提升格式版本

## 一、先选择接入等级

任务视图有快照和事件两条相互独立的取数路径。不要把“任务视图可零改动使用”理解成所有功能都不需要修改固件，也不要把完整自建协议理解成唯一接入方式。接入分为四档：

| 接入等级 | 典型改动 | 能获得什么 | 主要限制 |
|---|---:|---|---|
| L0 快照 | 通常不改固件 | 当前任务、任务列表、状态、优先级、栈水位、当前等待对象 | 短暂执行和短命对象可能完全看不到；时间线是采样近似 |
| L1 兼容事件 | 接入或复用现有 Trace/RTT/SWO | 现有格式能够表达的调度和业务事件 | 顺序、时间、对象身份分别按实际证据降级 |
| L2 句柄事件 | 增加轻量事件钩子 | 序号、时间戳、创建/删除和未截断的 32 位原生句柄 | 主机维护代次；历史名称可以未知 |
| L3 完整协议 | 集成完整事件组件 | 精确切换、生命周期、历史名称、缺口和撕裂检测 | RAM、Flash 和 CPU 开销最高；必须验证观察者效应 |

档位是能力集合的简称，不是主机写死的产品模式。一个目标可以同时提供 L0 快照和部分 L1/L2 事件，主机按实际能力逐项启用功能。推荐顺序是先接通 L0，再尽量复用 L1；需要可靠生命周期时做到 L2，需要完整历史和一致性保证时做到 L3。事件追踪不能替代硬件时序验收：低于 1 ms 且需要严格抖动证明的控制环，最终仍应使用 GPIO 标记、示波器、逻辑分析仪或硬件 Trace。

### 1.1 能力声明与协商

主机不根据档位名称乐观推断能力，而是读取或探测以下独立能力：

| 能力 | 目标或适配器需要证明什么 |
|---|---|
| `snapshot` | 可读取当前任务与内核对象 |
| `eventStream` | 可解码事件类型和边界 |
| `eventSequence` | 同一 epoch 内序号严格递增 |
| `timestampFrequency` | 时间戳来源、频率和变化边界明确 |
| `lifecycleEvents` | 创建、删除及复用可以区分 |
| `rawHandle32` | 32 位原生句柄未经截断或散列 |
| `targetDictionary` | 目标提供代次、名称和生效区间 |
| `atomicPublish` | 主机可识别并拒绝撕裂批次 |
| `epochBoundary` | 复位、重烧和重新启停记录有新边界 |
| `lossDetection` | 序号、计数或传输协议能揭示缺口 |

自建 L2/L3 组件应在事件头或只读描述块中提供带版本的能力位；第三方事件源由主机适配器声明其能够证明的能力；L0 能力可以根据 ELF/DWARF 和运行时探测得出。每项能力都有 `supported / unsupported / unknown` 状态及证据来源。声明与实际记录冲突时，主机以校验结果为准并报告冲突，不能继续按完整能力解释。

主机进一步为每项功能计算 `complete / degraded / unavailable / unknown`：能力齐全且数据通过校验才是完整；有明确替代路径但精度或覆盖下降是降级；确认缺少不可替代前提是不可用；尚未探测、证据冲突或无法消歧是未知。目标不需要为了达到较低档位伪造能力，也不能用零值或当前快照掩盖缺失的历史证据。

## 二、快照与符号解析需要的构建产物

凡是使用 L0 快照，或需要用符号文件为 L1/L2 事件补名称，主机读取的 ELF/AXF 都必须与目标当前运行的固件来自同一次构建，并满足以下要求。完全自描述的事件源可以不依赖 ELF，但必须明确把 `snapshot` 标为不支持，而不能假装具备快照能力。

- 保留完整符号表和 DWARF 调试信息，不向主机提供经过 `strip` 的文件。
- 保留结构体和成员信息；任务视图从 DWARF 读取 `TCB_t`、`List_t`、`ListItem_t` 和队列结构的实际偏移，不写死版本偏移。
- 保留 FreeRTOS 内核内部符号。开启 LTO、激进的未使用数据回收或符号隐藏后，应检查所需符号是否仍存在。
- 将链接映射文件与 ELF 一起归档，便于排查符号被回收、重命名或合并的问题。
- ELF 发生变化、目标复位或重新烧录后，必须开始新的采集会话，不能把新旧对象和时间轴静默拼接。

建议在固件 CI 中至少执行一次等价检查：

```text
1. ELF 可解析且包含调试信息
2. 必需内核符号存在
3. TCB_t/List_t/ListItem_t 的关键成员偏移可读取
4. ELF 构建标识与待烧录镜像一致
```

内核版本字符串不是稳定的链接符号。主机取不到版本时应显示“未知”，目标工程不需要为此人为导出一个假版本号；如项目需要可审计的精确版本，可额外导出只读的构建标识。

## 三、快照观察接入

### 3.1 必需符号

FreeRTOS 快照观察至少需要：

| 符号 | 用途 | 缺失结果 |
|---|---|---|
| `pxCurrentTCB` | 判断当前运行任务 | 任务视图不可用 |
| `pxReadyTasksLists` | 枚举就绪任务 | 任务视图不可用 |
| `pxDelayedTaskList`、`pxOverflowDelayedTaskList` | 判断阻塞和唤醒时刻 | 任务视图不可用 |
| `xSuspendedTaskList` | 判断挂起状态 | 任务视图不可用 |
| `xTickCount` | 内核时基和超时计算 | 相关时间字段不可用 |

以下符号存在时使用，缺失时降级：

- `xPendingReadyList`：调度器挂起期间待处理的就绪任务；
- `xTasksWaitingTermination`：已删除、等待回收的任务；
- `xSchedulerRunning`、`uxSchedulerSuspended`：解释调度器状态；
- `uxTopReadyPriority`：只作辅助，不依赖其跨配置语义。

这些内核对象可能是文件内 `static` 变量。构建完成后应直接检查最终 ELF，不能仅凭源码中存在就认为主机一定能找到。

### 3.2 FreeRTOS 配置影响

| 配置 | 作用 | 未启用时的降级 |
|---|---|---|
| `configUSE_TRACE_FACILITY=1` | 提供任务编号等辅助字段，也会触发常见端口的栈填充 | 基础任务枚举仍可工作，但部分字段不可用 |
| `configUSE_MUTEXES=1` | 暴露互斥量相关字段和基础优先级 | 不显示互斥量及优先级继承诊断 |
| `configQUEUE_REGISTRY_SIZE > 0` | 允许枚举已登记的队列、信号量和互斥量名称 | 同步对象面板只能显示快照能够从任务等待关系中发现的对象 |
| `configGENERATE_RUN_TIME_STATS=1` | 提供任务运行时间累计值 | 隐藏基于该计数的 CPU 占用列 |
| `configRECORD_STACK_HIGH_ADDRESS=1` | 提供栈边界辅助字段 | 依赖端口和分配方式推导，推导不可靠时不显示 |
| `configUSE_PORT_OPTIMISED_TASK_SELECTION` | 改变最高就绪优先级字段的语义 | 主机从就绪表数组自行计算，不要求关闭 |

要计算基于填充值的栈水位，FreeRTOS 构建中下列条件至少满足一项：

```text
configCHECK_FOR_STACK_OVERFLOW > 1
configUSE_TRACE_FACILITY == 1
INCLUDE_uxTaskGetStackHighWaterMark == 1
INCLUDE_uxTaskGetStackHighWaterMark2 == 1
```

`configCHECK_FOR_STACK_OVERFLOW == 1` 不足以保证栈填充。主机不能在缺少填充证据时把随机内存模式当成栈水位。

需要显示同步对象名称时，固件还必须调用 `vQueueAddToRegistry()` 登记相关队列、信号量和互斥量。未登记且当前没有任务等待的空闲对象无法仅靠内核链表发现，这是已知能力边界。

### 3.3 编译器与内核变体

- GCC、Arm Compiler 6、不同 FreeRTOS 版本和 MPU 端口会产生不同结构布局，必须以当前 ELF 的 DWARF 为准。
- `ListItem_t` 的容器字段在不同版本可能叫 `pvContainer` 或 `pxContainer`，主机适配层应接受版本别名。
- MPU 端口会向 TCB 增加字段，禁止复用普通端口的固定偏移。
- 开启列表完整性检查后列表结构会增加校验字段，禁止按默认布局解析。
- 使用 16 位 tick、tickless idle 或运行时改变系统主频时，必须让主机明确获知相应能力，不能沿用默认时间换算。

### 3.4 探针条件

J-Link、ST-Link 和 GDB Server 的普通模式可在目标运行时读取内存。串口后端需要目标固件集成配套读内存协议，因此不属于零改动接入。高速流式采样模式不能随机读取内核结构，任务快照应禁用。

运行态读取只能提供尽力而为的一致性。需要原子快照时，用户必须显式选择停核读取；主机不得为了方便而在后台静默暂停目标。

## 四、事件追踪组件要求

L3 事件追踪应作为独立目标侧组件接入，组件包含：

```text
rtos_trace_port.h       FreeRTOS hook 与统一事件的映射
rtos_trace_buffer.c/h   非阻塞事件缓冲和提交协议
rtos_trace_clock.c/h    时间戳、时基同步和 epoch
rtos_trace_dict.c/h     任务与同步对象的身份和生命周期（L3）
```

实际文件名可以不同，但 L3 的四项职责不能混成无法独立测试的一段宏代码。L2 可以不维护目标字典，但仍须记录创建、删除、epoch 和未截断的 32 位原生句柄。所有档位的热路径都不得调用 `printf`、动态分配内存或执行无界循环。

### 4.1 最低事件集

首版至少记录：

- 任务创建、删除、切入、切出、就绪、阻塞、唤醒；
- 优先级变化；
- 队列发送、接收、失败和超时；
- 信号量给出和获取；
- 互斥量加锁和解锁；
- 中断进入和退出；
- 时基同步与会话开始。

不同 FreeRTOS 版本可用的 `trace...` 宏不同。目标侧适配头负责把当前版本的 hook 映射到统一事件，不要求应用代码直接散落调用记录函数。编译时应对缺失的关键 hook 报错或显式声明能力降级，不能静默生成一条看似完整但缺事件的时间线。

### 4.2 对象身份与字典

L3 普通事件不能只记录会被复用的地址，也不能只记录没有来源的短编号。每个目标对象的稳定身份是：

```text
(kind, objectId, generation)
```

L3 目标侧必须遵守以下生命周期规则：

1. 创建任务或同步对象时，先建立字典项，再发布任何引用该对象的普通事件。
2. 字典项至少包含种类、编号、代次、原生句柄、名称和生效事件序号。
3. 删除对象时，先发布之前的普通事件，再关闭字典项的生效区间并保留墓碑。
4. 编号可以复用，但每次复用必须增加 generation，并在新普通事件之前发布新的字典定义。
5. 墓碑至少保留到目标缓冲中已经不存在引用它的事件；主机侧则保留到本地历史不再引用它。
6. 目标复位或重新启停记录时更换 epoch。不同 epoch 中相同的编号、代次和地址都不代表同一对象。

在 L3 中，内存环缓冲后端可以提供一张带生效序号区间的旁路字典表；RTT 和 SWO 流式后端必须在流中先发送字典定义/删除记录，再发送依赖它的事件。名称长于协议上限时应按 UTF-8 字符边界截断并显式标记，不能截出非法 UTF-8。

周期快照只负责补充当前优先级、栈范围和等待对象等动态字段，不能代替历史身份证据。一个任务可能在两次快照之间完成创建、运行和删除：L3 依靠目标字典恢复名称与生命周期，L2 依靠原始句柄和生命周期事件区分身份但允许名称未知；两者都没有时，主机不能从后续快照倒推出这段历史。

**L2 兼容路径：** 如果目标难以维护上述字典，可以在每条相关事件中记录完整的 32 位原生句柄，并记录创建和删除事件。主机据此建立 `(sessionId, epoch, kind, rawHandle32, hostGeneration)` 映射，在创建时增加代次、删除时关闭区间。原生句柄不得截成 16 位、散列成短编号或只保留低位。缺少创建/删除、记录从中途接入或句柄复用无法消歧时，主机必须结束旧映射并标为未知；周期快照只能给当前对象补临时名称，不能倒填历史。

### 4.3 普通事件格式

自建事件源的普通事件固定为 16 字节、小端编码：

| 偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 4 | 同一 epoch 内严格递增的事件序号 |
| 4 | 4 | 目标周期计数低 32 位 |
| 8 | 1 | 事件类型 |
| 9 | 2 | 任务编号 |
| 11 | 2 | 对象编号 |
| 13 | 3 | 按事件类型解释的参数 |

协议版本必须为每个事件类型定义参数的有无、单位、符号性和溢出行为。未定义参数不能由主机猜测。上述 16 字节格式属于 L3 自建协议；L2 若需要携带 32 位原生句柄，必须使用有版本的扩展记录或第三方格式，禁止把句柄硬塞进 16 位编号。第三方记录库使用自己的线格式，主机解码后再映射到统一事件模型，不要求强行转换成上述目标格式。

每个事件缓冲头至少声明：格式版本、epoch、核编号、时钟来源、时钟频率、写位置、累计提交数、覆盖数、拒绝数和头部 generation。多核目标每个核使用独立缓冲，并由主机按时间映射合并。

### 4.4 事件提交和并发

16 字节记录不是原子写入。目标侧必须采用明确的发布协议，避免主机读到半条记录：

1. 进入有界的写入临界区，将覆盖整个事件区提交过程的头部 generation 改成奇数；
2. 预留槽位，写入时间戳、类型、编号和参数；
3. 执行适合目标架构和编译器的发布屏障；
4. 最后写入序号；
5. 更新头部的已提交计数和写位置；
6. 再执行发布屏障，将 generation 改成下一个偶数并退出临界区。

generation 必须覆盖事件槽和头部字段的整个修改过程，不能只包住头部自身。否则环缓冲覆盖旧槽位时，主机可能看到旧序号配上新负载。主机仅在读取前后的 generation 相同且为偶数时接受该批数据，并继续校验每条序号与预期位置一致；范围在读取期间被覆盖或记录未提交时，标记缺口并重试有限次数，不得拼接出伪事件。

如果任务和 ISR 都可能写入，目标侧必须选择一种有界策略：短临界区保护预留与提交，或者经过验证的单生产者/多生产者算法。禁止在高优先级中断、NMI 或 fault 上下文调用会获取普通 RTOS 锁的记录路径。嵌套写入无法安全处理时，应拒绝该事件并增加拒绝计数，而不是阻塞。

### 4.5 缓冲满策略

事件记录永远不得等待主机释放空间。每个后端必须声明且只使用非阻塞策略：

- 自建内存环缓冲默认覆盖最旧记录，并累计覆盖数；
- 无法进入记录路径或主动放弃的新事件累计拒绝数；
- RTT 使用 skip/trim 等非阻塞模式，禁止阻塞等待模式；
- SWO 发送失败必须可检测并反映为序号缺口或丢失计数。

覆盖数、拒绝数和事件序号缺口是不同证据，主机分别展示，不能只合成一个无法解释的“丢失”数字。

## 五、时间戳与会话边界

### 5.1 时间戳来源

Cortex-M3/M4 首选 DWT 周期计数器。固件负责确认计数器存在、启用并持续运行；主机不得为了事件追踪而偷偷写调试寄存器。若芯片、低功耗模式或安全配置不允许使用 DWT，目标端必须明确声明退回内核 tick，主机相应降低时间精度。

目标侧应导出或在缓冲头声明实际计数频率。不能只把编译期 `configCPU_CLOCK_HZ` 当作运行期事实。系统运行期间改变主频、进入会停止计数器的睡眠状态或启用 tickless idle 时，应发布新的时基同步记录。

### 5.2 epoch

以下情况必须生成新的非零 epoch：

- 目标复位或重新烧录；
- 事件记录从停止变为开始；
- 时间计数器重新初始化；
- 事件格式、缓冲或传输后端切换；
- 无法证明时间连续性的连接恢复。

epoch 改变是硬会话边界。主机可以同时保留前后历史，但必须显示断点，不能跨边界计算持续时间、阻塞归因或对象生命周期。

32 位周期计数允许在同一 epoch 内按模 2^32 回绕，主机利用严格递增的事件序号和同步记录扩展为 64 位。事件序号不允许在同一 epoch 内回绕：接近 `0xFFFFFFFF` 时，目标必须先结束当前 epoch，再以新 epoch 和序号 1 继续。这样字典生效区间、丢失检测和分页游标都没有模运算歧义。出现无法消歧的长时间断连时，结果标为未知。

## 六、传输后端要求

### 6.1 内存环缓冲

- 不需要额外引脚，主机通过普通读内存接口分批下载。
- 缓冲头使用奇偶 generation 或等价机制防止撕裂；事件槽或头部更新期间为奇数，整批数据稳定后才发布偶数。
- 字典表与事件缓冲使用同一 epoch，并带自己的容量和 generation。
- 缓冲大小按“峰值事件率 × 希望保留的异常前后窗口”计算，而不是只按平均事件率计算。

### 6.2 RTT

- 目标工程链接 SEGGER RTT 或明确兼容的记录库，并保留 `_SEGGER_RTT` 控制块或提供确定的发现方式。
- 事件使用独立上行缓冲，禁止与文本日志混用同一通道。
- 必须使用非阻塞写模式；阻塞模式不符合本契约。
- 多个执行体写入时使用有界的并发保护；无锁写仅允许确定的单写入者。
- 主机读取 RTT 后会更新读位置，因此 RTT 不是“主机绝对只读”模式。

### 6.3 SWO/ITM

- 芯片、板级设计和探针必须支持并引出 SWO。
- 固件声明核心时钟、SWO 波特率、ITM 端口和编码版本。
- 事件与其他 ITM 输出分配不同端口或使用可区分的帧协议。
- SWO 带宽不足时优先保留切换、阻塞、唤醒和中断事件，文本及低价值参数事件先降级。

## 七、资源与实时性要求

目标侧接入说明必须给出本构建的实际资源数字：

| 指标 | 必须报告 |
|---|---|
| Flash | 组件引入前后差值 |
| 静态 RAM | 事件缓冲、字典、控制块总量 |
| 每事件开销 | 平均值、最大值及测试时钟频率 |
| 最长关中断时间 | 任务和 ISR 写入路径分别测量 |
| 丢失能力 | 峰值事件率下多久覆盖一圈 |
| 控制周期影响 | 关闭、轻量和完整记录三档的周期与抖动 |

建议提供三个编译等级：

| 等级 | 事件内容 | 用途 |
|---|---|---|
| 关闭 | 不编译记录调用或编译为空操作 | 生产基线 |
| 轻量 | 切换、阻塞、唤醒、中断、字典 | 常规实时分析 |
| 完整 | 再加入 IPC 结果、队列深度和诊断参数 | 专项问题定位 |

无论哪个等级，热路径都必须有固定上限；缓冲满、主机断开或探针变慢不能增加目标侧等待时间。

## 八、失效与降级行为

目标侧或主机检测到下列情况时，应保留已有可信数据并显式降级：

| 情况 | 行为 |
|---|---|
| 必需内核符号缺失 | 禁用快照观察，列出缺失符号 |
| 可选 FreeRTOS 配置缺失 | 隐藏相关列或诊断，不填伪值 |
| 字典定义缺失 | 对象显示为未知，不按当前快照错误套名 |
| 事件序号缺口 | 时间线画缺口，因果链在此终止 |
| 半写记录或头部撕裂 | 有限重试，失败后跳过该批 |
| epoch 改变 | 建立新会话段，清空跨段推导状态 |
| RTT 为阻塞模式 | 拒绝开始事件追踪并说明原因 |
| 时间频率未知 | 保留原始 tick/cycle，不显示伪精确秒数 |
| 能力尚未探测或证据冲突 | 对应功能标为未知，显示证据与下一步检查，不按完整或不可用处理 |
| 只有 32 位句柄而无目标字典 | 使用主机生命周期映射；名称未知不影响身份，无法消歧时断开映射 |

## 九、目标侧验收清单

### 9.1 构建检查

- [ ] ELF/AXF 与烧录镜像来自同一次构建。
- [ ] ELF 含符号表和 DWARF，主机能读取关键结构偏移。
- [ ] 必需内核符号没有被 LTO 或链接回收。
- [ ] FreeRTOS 配置能力矩阵与实际构建一致。
- [ ] 能力描述的版本、能力位和主机实测结果一致；不确定项保持 `unknown`。
- [ ] 队列、信号量和互斥量按需要加入注册表。

### 9.2 快照检查

- [ ] 能区分运行、就绪、延时阻塞、无限期阻塞、真正挂起和待删除。
- [ ] 栈水位与 `uxTaskGetStackHighWaterMark()` 的结果一致。
- [ ] 优先级继承期间能看到当前优先级与基础优先级不同。
- [ ] 目标运行态读取失败不会被误报成“没有任务”。

### 9.3 事件检查

- [ ] 第一个普通事件之前已经存在对应字典定义。
- [ ] 短命任务在两次快照之间创建并删除后仍能还原名称。
- [ ] 地址或编号复用后，新旧对象不会串名。
- [ ] 在记录写到一半时读取，主机不会接受半条记录。
- [ ] 时间戳回绕能正确扩展；事件序号到上限前会切换 epoch，同一 epoch 内的序号回落会被拒绝。
- [ ] 缓冲覆盖、主动拒绝和传输丢失都可检测并分别计数。
- [ ] 主机断开期间目标不会阻塞。
- [ ] L2 的 32 位句柄未被截断，创建、删除和复用能驱动主机代次变化。

### 9.4 实时性检查

- [ ] 分别测量关闭、轻量和完整记录三档。
- [ ] 测量任务上下文和 ISR 上下文的最坏记录耗时。
- [ ] 测量控制周期、最大抖动和最长关中断时间。
- [ ] 峰值事件率下缓冲保持时间符合项目要求。
- [ ] 测试结果记录芯片、主频、编译器、优化等级和传输后端。

## 十、仓库中的验证资产

现有验证固件位于：

```text
example/rtos_trace_port/firmware/
```

它已经覆盖任务状态、队列、信号量、互斥量、栈水位、优先级继承和已知周期任务，可用于 L0 快照观察验证。当前它还不是完整的目标侧事件追踪组件；加入事件记录时至少要声明实际能力，L2 落实句柄、生命周期和 epoch，L3 再落实字典、一致性提交和丢失协议。

固定事件样本位于：

```text
test/eventSamples/
```

这些样本用于主机解码器回归，不能替代在线并发测试。当前正例覆盖环形重组、丢失、时间戳回绕、对象代次和跨 epoch 隔离；`invalid/` 负例覆盖奇数 generation、截断、越界、半写事件、字典缺失与重叠、未切 epoch 的序号回绕和未对齐写指针。上线事件后端前仍需补目标真机上的头部变化与嵌套写入测试。

## 十一、接入完成的判据

目标侧接入必须声明完成到哪一档，不能用 L3 要求否定已经合格的较低档位，也不能把较低档位宣传为完整追踪。所有档位共同满足：

1. 未启用事件组件时，固件的运行行为和资源基线不受影响。
2. 快照观察明确报告可用能力和降级项。
3. 主机对每项功能明确输出完整、降级、不可用或未知及其原因。
4. 已声明支持的能力都有构建检查或运行时证据，声明冲突不会被静默忽略。
5. 目标在缓冲满、主机断开和事件突发时始终非阻塞。
6. 主机不跨无法证明的缺口、复位或身份边界生成连续时间线。
7. 实测资源与实时性数据随示例和发布文档一起提供。

各档位另有以下完成条件：

| 档位 | 完成条件 |
|---|---|
| L0 | 快照字段逐项报告来源、一致性和缺失项，短时行为明确标为采样近似 |
| L1 | 适配器列出能够证明和不能证明的事件能力，未知字段不猜测 |
| L2 | 事件流用完整 32 位句柄和生命周期事件独立区分短命、删除与复用对象；无法消歧时断链 |
| L3 | 目标字典、原子发布、epoch 和丢失检测全部通过本文件的事件与并发验收 |
