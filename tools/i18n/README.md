# Interface translation toolchain

Variable-Trace is written in English and shows Chinese on request. Every piece
of interface text a reader sees goes through `I18n::tr`, which looks the English
up in a table and returns the Chinese for it. This directory holds the scripts
that build that table from the source, and the two data files they read and
write.

Nothing here runs during a build. The table is generated by hand when interface
text changes, and the result - `src/I18n/I18nTable.inc` - is committed along with
the rest of the source.

## Files

| File | What it is |
| --- | --- |
| `i18n_apply.py` | Wraps call sites in `I18n::tr(...)`, and reports what has no translation yet |
| `i18n_table.py` | The Chinese translations themselves, written by hand, and the pass that writes `i18n_dict.json` |
| `i18n_gen.py` | Turns `i18n_dict.json` into `src/I18n/I18nTable.inc` |
| `i18n_includes.py` | Gives every file that asks the table for text its `#include "I18n.hpp"` |
| `i18n_extract.py` | Collects the literals that can reach the screen |
| `i18n_leftovers.py` | Prints every literal the collection pass walked past |
| `i18n_review.py` | Prints prose that is nowhere in the table |
| `i18n_sites.json` | The English strings, in the order the translations are written against. 237 entries, frozen - see below |
| `i18n_dict.json` | The finished dictionary, English to Chinese. 399 entries |

## The chain

Run these three in this order. Only the last one produces something the
application reads.

1. **Wrap the call sites.**

   ```
   python tools/i18n/i18n_apply.py apply tools/i18n/i18n_dict.json
   ```

   This rewrites `ImGui::Text("foo")` into `ImGui::Text(I18n::tr("foo"))`, and
   prints the strings it found that have no translation. That list is the work
   for the next step.

2. **Write the translations.**

   ```
   python tools/i18n/i18n_table.py
   ```

   The Chinese is authored by hand in this script, in the `TRANSLATIONS` list. A
   `None` in that list means the string is not language at all - an identifier, a
   symbol, a proper noun - and it is neither translated nor wrapped. The pass
   pairs the list with `i18n_sites.json` and writes `i18n_dict.json`.

3. **Generate the table.**

   ```
   python tools/i18n/i18n_gen.py
   ```

   Writes `src/I18n/I18nTable.inc`. The entries come out sorted by their English,
   which is the order the look-up bisects instead of walking the whole list on
   every frame.

Rebuild afterwards.

## The checks

None of these writes anything. They answer different questions, and it is worth
running all three after a pass.

- `python tools/i18n/i18n_includes.py`

  Files that call `I18n::tr` without including `I18n.hpp` do not compile, so
  this always reports zero in a state that builds. Add `apply` to write the
  includes in.

- `python tools/i18n/i18n_review.py tools/i18n/i18n_dict.json`

  Prose that is in neither the table nor a call to `tr`. The list holds false
  hits as well - log lines, GLFW format strings, shader sources - so it is meant
  to be read, not counted.

- `python tools/i18n/i18n_leftovers.py tools/i18n/i18n_sites.json`

  Every string literal in the interface files, marked with whether the
  collection pass picked it up.

## `i18n_sites.json` is frozen

**Do not regenerate this file to pick up new strings.**

The translations are a plain list in `i18n_table.py`, and they are matched to
the English list by position: entry 40 of one is the Chinese for entry 40 of the
other. The two lists mean the same thing only while they are the pair that was
written together.

Regenerating the English side from the current source moves every string that was
added or removed, and from that position on each Chinese line belongs to a
different English line. Nothing complains. The counts still match, the table
still builds, and the interface comes up with the wrong Chinese on hundreds of
labels - a mismatched pair is invisible at run time, because the fallback for a
missing entry is simply the English.

Both collection passes add to this: they pick up literals that are **not already
wrapped**, so neither can rebuild the file. `i18n_extract.py` and
`i18n_apply.py list` each report nine strings today, against the 237 this file
holds.

### Adding strings

Extend `i18n_sites.json` and `TRANSLATIONS` together, and leave the positions of
the entries already there alone. Appending to both is the only edit that cannot
disturb the pairing.

The length check in `i18n_table.py` catches a list that was replaced with a
different one. It cannot catch a list that was reordered or had entries inserted
in the middle, and those are the mistakes that do the damage.

## Working directory

Every script resolves the repository root from its own location, so any working
directory will do. The commands above are written for the repository root, where
the relative paths to the two JSON files read most clearly.
